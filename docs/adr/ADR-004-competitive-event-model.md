# ADR-004 — Competitive event model

**Status:** Accepted · **Date:** 2026-09-03

The crown jewels. Everything else in the platform is derived from this.

## Decision — the schema contract

```
evidence.event
  event_id          uuid PK          -- UUIDv7, generated by the writer
  stream_id         text             -- 'match:{uuid}', 'event:{uuid}', 'player:{uuid}'
  stream_seq        bigint
  global_seq        bigint  identity
  event_type        text
  schema_version    int
  rules_version     text             -- ruleset pinned to the match at open
  engine_version    text
  actor_id          uuid
  actor_role        text             -- participant | official | venue_scorer | system
  device_id         uuid
  occurred_at       timestamptz      -- device clock: EVIDENCE ONLY
  occurred_tz       text             -- IANA zone id, stored separately
  recorded_at       timestamptz      -- server clock: ORDERING AUTHORITY
  corrects_event_id uuid  references evidence.event
  payload           jsonb
  UNIQUE (stream_id, stream_seq)
```

Six properties, each of which is independently load-bearing.

**1 — `UNIQUE (stream_id, stream_seq)` is the concurrency control.** Appending with an expected next
sequence gives compare-and-swap for free via the unique index. This one constraint is what makes
concurrent writes safe without locks, and it provides the per-stream total order that replay and
client deduplication depend on.

**2 — Append-only is a database grant, not a convention.** `REVOKE UPDATE, DELETE ON evidence.*`.
Corrections are new events carrying `corrects_event_id`, a reason and an authoriser. CI asserts the
grant.

**3 — Command receipts are written in the same transaction as the append.**

```
evidence.command_receipt
  device_id, client_command_id  PK    -- idempotency key, scoped per device
  outcome, reason_code, resulting_event_ids, response_body
```

A retry returns the stored response **verbatim, including a stored rejection**. Written in a separate
transaction, a crash between the two either double-applies a visit or loses the receipt.

**4 — Do not tail `global_seq` naively.** Identity values are assigned at insert time, not commit
time, so a reader polling for values above a watermark will **silently skip** events from
transactions that started earlier and committed later. Projectors and the realtime dispatcher consume
only to a watermark derived from the oldest in-flight transaction. This is the classic silent
corruption bug in exactly this architecture and it is called out here so nobody rediscovers it.

**5 — Ordering never depends on wall clock.** Order by `(device_id, stream_seq)`; `occurred_at` is
evidence, `recorded_at` is authority. Record the observed device clock offset so skew is *visible*
rather than silently corrupting the graph. **A wrong clock is not a cheating signal** and must never
reject an event.

**6 — Visit totals and dart-level evidence are structurally distinct.**

```
evidence.visit(visit_id, leg_id, thrower_id, visit_seq, total int,
               darts_used int NULL, bust bool, checkout bool, remaining_after int)
evidence.dart(visit_id, dart_index, segment int, multiplier int)   -- 0..N rows, OPTIONAL
```

Absence of dart rows is a legitimate terminal state meaning **unknown** — never zero, never inferred.
`darts_used` is nullable and exists in schema v1 **whether or not the first release prompts for it**,
because adding it later creates a permanent unknown cohort.

## How this keeps blockers B1 and B2 open

- **B1** (which statistics ship, and whether `dartsUsed` is captured) — the field exists and is
  nullable from v1, so either answer works without migration. Statistics cross the API as
  `{value, basis: EXACT | BOUNDED | UNAVAILABLE, evidenceLevel, sampleSize}`, so an honest
  "unavailable" is representable before the product decides whether to show it.
- **B2** (whether a unilateral self-report moves rating) — eligibility is an **orthogonal axis**
  carried as its own event stream, not a value of the provenance enum, and the eligibility *rule* is
  configurable policy rather than a hardcoded predicate.

**CI gate:** run the full statistics and rating suite against a corpus containing zero dart rows and
assert that every dart-level metric returns unavailable rather than a number. This is the mechanical
guard against the failure the brief most wants prevented.

## Provenance and trust

The verification label is **derived, never stored**. Store the composite: capture channel, entering
actor, each confirming actor with timestamp and role, competition and board context, organiser
authority with the named individual, device and connectivity, submission and occurrence times, the
full confirmation history, corrections, and integrity signals attached at ingest. Storing only the
enum means trust can never be re-derived under a changed policy and two results reaching the same
label by different routes become indistinguishable.

**Confirmation attaches to the leg**, per participant. Match state is derived from its legs.

**Outcome type is first-class**: `played`, `walkover`, `forfeit`, `retired`, `awarded`, `void`,
`replayed`. A walkover stored as a scoreline is indistinguishable from a played one forever and
poisons every rating model trained on it.

## Consequences

- Corrections create auditable history and never overwrite.
- Read models live in their own schema, are written only by projectors, and must be fully
  rebuildable — asserted in CI by truncating, replaying a fixture log, and comparing byte-for-byte.
- Identity is separable: events carry an opaque player reference only, so the design's deletion
  promise ("results remain, without your name attached") is implementable.

## Revisit trigger

Event table beyond ~200M rows (partition by month); or a projector unable to stay within seconds of
the watermark under tournament load.
